# 實盤驗證：選股報告 × 實際盤價（推薦執行輸多少）

## When this is needed
把「某日選股報告的入選檔」按原進場/停損/TP1/TP2，套「隔日實際已定案 OHLC」，用同一策略判定函數算出每檔與累積的毛/淨 PnL，產出 `results/實盤驗證_YYYYMMDD.md`；若用戶要求「更新某報告」，再此節併入該檔（如 `報告_TP1半倉拚TP2_2026.md`）。這是選股報告之後的執行驗證環。

## 資料來源
- 入選清單：`compare_v1_v2_dated.py --date <D>` → `results/compare_dated_<D>.json`，或對應 `選股報告_*.md`（含每檔 entry/sl/tp1/tp2）。**直接用報告的位，不要重算**——用戶是按報告執行。
- 判定函數：`backtest_tp1half_tp2.py::evaluate()`（半倉拚TP2：A達TP1後B移到保本停損，故凡達TP1者皆贏）。單目標策略改用對應 evaluate。
- 抓取：`scanner.yahoo_chart(f"{code}.TW", rng="5d", interval="1d")` + `parse_bars()`，取 `rows[-1]` = 隔日實際行情。

## 步驟
1. 讀入昨日報告每檔的 entry/sl/tp1/tp2（原值）。
2. 每檔抓 `yahoo_chart(...)` → `parse_bars()` → 取最後一支棒。
3. **守衛：確認是「已定案」日線再判定**（見坑 #1）。
4. `evaluate({entry,sl,tp1,tp2}, bar)` → triggered / pnl(毛) / pnl_net(扣費) / outcome / profit。
5. 彙總：實際觸發筆數、獲利/虧損筆數、勝率（分母=實際觸發）、累積毛 PnL、累積淨 PnL（元/股）；×1000 得每張金額。
6. 寫 `results/實盤驗證_YYYYMMDD.md`；用戶要更新來源報告時，把此節併入該檔。

## 必記坑
- ⚠️ **收盤前不要用當日棒當已定案**：Yahoo 在 13:30 收盤前會回未定案的「今日」棒（價格/成交未定型）。判定前先確認①現時 Asia/Taipei > 13:30、②`rows[-1]["date"]` == 預期交易日。任一不符就等收盤後重跑，別把 intraday 當 final。
- ⚠️ **「未觸發」不是虧損**：triggered = (h ≥ entry) or (o > entry)。跳空低開、全日沒摸到進場價的檔 → 不觸發 → 不交易、PnL=0。這是規則保護（避開跳空被洗），報告要標「未觸發/錯過」並明寫「零損失」，**不算勝率分母、也不當虧損列**。
- ⚠️ **勝率分母 = 實際觸發，不是入選檔數**：與回溯一致（未觸發不計）。同時給「觸發內勝率」與「幾檔未觸發」兩數，避免誤導。
- ✅ **費用**：evaluate() 已內建當沖最高費（買 0.1615%、賣 0.4615%）算 pnl_net。報告同時給毛與淨；並註明多數券商當沖免手續費，真實净利更高。
- ✅ **解讀連回策略邏輯**：達TP1的檔靠「A鎖利+B保本」必贏（對應回溯「達TP1全獲利/平手」支柱）；停損檔是回溯 32.7%「唯一短板」的實盤翻版。誠實標小樣本、Yahoo 歷史棒後修會使數字漂移。

## 報告格式
- 逐檔表：代號／名稱／進場／停損／TP1／TP2 ＋ 當日 O/H/L/C ＋ 結果（達TP1+TP2／達TP1(另一半保本)／停損／收盤了結／未觸發）＋ 毛(元/股) ／ 淨(元/股)。
- 汇总表：入選檔數、實際觸發筆數、獲利/虧損、勝率、累積毛 PnL、累積淨 PnL（+每張換算）。
- 誠實解讀：贏/虧來源、未觸發是否為保護、與回溯基線的對應、樣本與漂移限制。
