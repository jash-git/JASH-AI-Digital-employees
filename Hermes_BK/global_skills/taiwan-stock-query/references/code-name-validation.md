# Code↔Name Validation & Data-Integrity Audit

Recipe for auditing a Taiwan stock code→name list (universe CSV, report labels) against ground truth.

## Authoritative source: T86

```bash
curl -s "https://www.twse.com.tw/rwd/zh/fund/T86?selectType=ALL&response=json" -H "User-Agent: Mozilla/5.0" > t86.json
python3 -c "import json; d=json.load(open('t86.json')); print({str(r[0]).strip():r[1].strip() for r in d.get('data',[])})"
```

`d['data']` rows are `[代號, 名稱, ...]`. `name` is the official TWSE Chinese name. ~21k rows, reachable even when `STOCK_ALL`/`STOCK_IEX`/`ETF_*` return empty.

## Validation loop (per code)

```python
import json, urllib.request, ssl
d = json.load(open('t86.json'))
m = {str(r[0]).strip(): r[1].strip() for r in d.get('data', [])}
ctx = ssl.create_default_context(); ctx.check_hostname=False; ctx.verify_mode=ssl.CERT_NONE
ua = 'Mozilla/5.0'
def meta(c):
    try:
        j = json.load(urllib.request.urlopen(
            urllib.request.Request(f'https://query1.finance.yahoo.com/v8/finance/chart/{c}.TW?range=1y&interval=1d',
                                   headers={'User-Agent': ua}), timeout=15, context=ctx))
        return ('timestamp' in j['chart']['result'][0])   # True = real historical data exists
    except Exception:
        return False
```

Decision per code:
- **T86 has it** → use T86's official name (authoritative). Yahoo `shortName` should match; if not, trust T86.
- **Yahoo 404 + T86 absent** → code does not exist in this environment. Find the intended stock by searching T86 for the Chinese keyword (`'聯電' in r[1]`, `'創意' in r[1]`), then confirm that candidate with `meta()` before adopting.
- **Keyword search returns only 認購權證 (warrants, codes like `072756`)** → pick the underlying 4-digit stock, not a warrant. e.g. 聯電 = 2303, 創意 = 3443.

## Pitfalls

- **Trust live cross-check between two authoritative sources (Yahoo + T86), not memory.** This environment maps `2454=聯發科`, `2408=南亞科` — the opposite of real-world `2408=聯發科`. Both agree here, so the mapping is internally consistent; do not "correct" it to match your prior knowledge.
- **Prices are correct even when labels are wrong.** A mislabeled row still shows a real price for the *actual* code — that's why the report looked plausible. Fix names only; prices/scores/backtest results are unaffected by label corrections.
- **A stock-list CSV with N duplicate/wrong codes can silently select the wrong security.** e.g. `2377` labeled 台積電 actually selects 微星 (155元); real 台積電 is `2330` (~2575). The scanner dedupes by code, so one bad row per code still lands.
- **write_file refuses to overwrite a file it hasn't seen in full.** Read the whole file first (`read_file`, all pages) before overwriting; partial views trigger a stale-write block.

## Report generation note

Scanner scripts emit only CSVs — no `.md` report is generated by any script. A markdown report was hand-written from the CSV, so it inherits whatever name errors were in the CSV at write time. After fixing `universe.csv`, regenerate the report from the corrected CSV; re-run backtests to fix historical reports too.
